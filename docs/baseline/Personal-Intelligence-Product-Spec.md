# SecondBrain — Personal Intelligence：产品总目标、目标架构与实施路线

> **效力与阅读顺序：** 本文件记录用户于 2026-10-16 明确批准的产品最高目标、体验原则、演进方向和验收要求。现有 `SecondBrain-Web-App-V1-Business-Spec.md`、`Universal-Capture-Business-Spec.md` 的既有 MUST 不取消；本文件新增智能伙伴能力与优先级，并由 `00-CURRENT.md` 跟踪状态、`Architecture.md` 记录稳定技术边界、`Decision-Log.md` D077 记录批准与替代关系。具体实现方案在隔离验证前不视为已批准上线。

## 1. 最高产品目标（APPROVED）

SecondBrain **不是收到“检索”指令才搜索文件的知识库聊天助手**。它应成为一个长期了解用户、能够伴随互动共同成长、自然运用历史知识与个人认知、主动发现问题并帮助提前思考和规划的个人 AI 伙伴。

### 不可退让的产品标准
1. **默认自然联想。** 日常对话不需要用户指定“查询知识库”。系统在回应前自动判断当前主题与哪些长期记忆、项目、日记、已有知识相关，并在相关时运用；必要时无感读取可信来源核对细节。
2. **持续形成并修正个人认知。** 自动学习获准互动中体现出的偏好、习惯、长期目标、关键经历、经验和改变原因；跨会话有效、可检查、可纠正、可淘汰过期认知。
3. **知识与记忆有别。** 原件与正式知识是事实证据；AI 推断是可错、可修正的个人认知。禁止把推断、情绪或第三方材料写成已核实的用户事实。
4. **自主学习、有限自主行动。** 一般记忆学习默认允许，不逐条让用户审批；正式 Knowledge Promote、核心 Skill/权限修改、重大生产或外部动作遵守对应授权。
5. **主动但不打扰。** 能依据目标、任务、项目进展和历史经验提出有依据的建议；可控频率、可关闭、可查看来源，不把建议冒充已执行结果。
6. **技术为目标服务。** Hermes、分层记忆、loop、检索、知识关联都是实现手段；不因新技术流行而增加 Jev、世界模型、图数据库或第二 Agent Runtime。效果优先于技术名称。

**非目标：** 将全部文件训练进基础模型参数；让 AI 永不检索原件；无需证据就声称“完全懂你”；自动完成未授权的真实世界操作。

## 2. 最初日常需求必须完整保留（APPROVED）

| 自然使用场景 | 目标行为 | 数据/授权规则 |
|---|---|---|
| 碎碎念、随手记、日记、心情、语音转文字 | 用户表达“记一下/写日记”时直接记录原话、时间、来源，支持按日追加 | `50-Journal` 专用新增/追加，不覆盖或删除原文；按 D064 不经 Review；Journal 写入尚未上线 |
| 待办、提醒、日程 | 以自然语言创建/查看/调整/完成任务；和当天 Journal、Today/Calendar 关联；通知要验真实送达链路 | 沿用 D064 日期时间轴，不预建 `60-Tasks`；明确行动意图可直接入授权业务区，实际提醒能力未验收 |
| 丢文件、链接、文本、图片、PDF、音频 | 保存 Raw；提取/转写；摘要、主题分类、建议关联，形成 Review；获批准才进入正式知识 | Universal Capture v1.1；微信和 Web 都是输入渠道；非文本质量、微信/STT 等仍有缺口 |
| 普通聊天、方案讨论、纠正 AI | 默认与 Hermes 对话；自动关联已有记忆；对话后提炼偏好和经验，未来对话复用 | **普通聊天不等于自动写 Journal / Raw / 正式 Knowledge**；授权对话可生成“个人记忆”，不等同于知识入库 |
| 提前思考和规划 | 结合项目、任务、时间线、近期关注点提出下一步建议或风险提示 | 建议先入 Inbox/Home/Today 的建议区；实际执行需动作级权限和用户授权 |

**重要意图区分：** 继续保留 D076“普通 Chat 不自动视为收录指令”原则，但将“聊天中自动学习受限个人记忆”明确排除在“自动 Capture/Promote”之外。对明确记日记、建立待办、收文件等请求可从自然语言入口路由；模糊/高风险动作询问确认，避免强制手动切换模式或擅自保存整段聊天。

## 3. 双闭环：个人学习与正式知识（APPROVED）

### A. Personal Learning Loop（默认允许，低风险）
获准互动/可访问业务事实 → 发现候选偏好、事件、目标变化或可复用经验 → 分类/去重/与旧记忆比较 → 保存带来源和时间的个人记忆/候选 Skill → 下一轮对话自动召回 → 依据用户纠正和真实结果修正、失效或替代。

- 必须区分用户明确陈述、经多次验证的规律、模型推断；允许“不确定”。
- 防止无限累积：相似记忆合并，矛盾记忆有时间与冲突状态，支持撤销与追溯；不过度将短期情绪、随口假设提升为稳定人格判断。
- 一般偏好/经验可以自动写入**限定记忆区**；核心 Skills 的生产发布、具有文件写入/执行风险的 Skill 变更仍按 Skill 审核边界。
- 记忆跨模型、跨会话、跨 Hermes 版本可迁移；不得仅依赖 Hermes session、内部 state.db 或不可导出的提供商存储。

### B. Knowledge Integrity Loop（保留人工确认）
明确收录/文件上传 → Raw 不覆盖保存 → 可核验提取/分析 → Review → 用户批准 → 受控 Core Promote → `20-Knowledge` → 检索/引用/更新建议。

- 正式 Knowledge 不允许 Hermes 自动 Promote，也不应因为允许自动记忆而放宽。
- Journal/Task 属于已授权的业务记录，不应全部绕道知识审批；从 Journal 提升到正式 Knowledge 仍需 Review/Promote。
- 外部文件的 AI 摘要可作为待核实的索引线索，不得取代原文或伪造结论。

## 4. 分层记忆：逻辑模型而非四套存储（目标方向，具体存储设计待验证）

- **L1 Core Identity / Preferences：** 高频且稳定的身份、偏好、目标、约束；内容少、优先注入对话上下文。
- **L2 Active Context：** 当前项目、关系、待办、时间线、近期主题及待决问题；按话题和新鲜度选取。
- **L3 Episodic & Learned Experience：** 关键日记、事件、决策过程、失败教训、用户纠正与行动结果；能指向原始时间和来源。
- **L4 Evidence & Knowledge：** 完整 Journal、Projects、正式 Knowledge、Raw/Review（按权限）与原始文件；在需要精确事实时按需核对。

Hermes 的原生记忆/Session/Skills 是**运行能力与可用缓存**；SecondBrain 的可导出个人记忆与文件知识是业务上可恢复、可审计的持久资产。是否使用 Hermes 原生 Memory Provider、上下文预载钩子或 App/BFF 的最小适配，**先调查实际版本与兼容性，不能凭最新文档直接当作现有生产功能**。

初期可用轻量 Markdown/JSONL/受控 Core state 实现，沿用已有 `40-Memory` 与授权的数据区；物理路径、版本策略、索引、接口契约由隔离原型和数据恢复测试后确定。默认不建设并行正式知识库、向量数据库、图数据库或新的记忆微服务。

## 5. 目标技术架构与数据流（APPROVED 边界，内部细节候选待证）

```text
Web / WeChat（已验证后）/ 授权客户端
    └── SecondBrain App（唯一业务入口：UI + App Session + Core/BFF）
          ├── Natural-Language Intent：Chat / Journal / Task / Capture
          ├── Capture → Raw → Review → Human Promote
          ├── Journal / Task / Calendar / Projects / Home
          ├── Personal Memory（受控记忆写入、来源、版本、纠错、召回）
          ├── Organizer（授权会话整理；与记忆学习职责分离）
          ├── Proactive Suggestions（目标/事件触发、去重、节流、状态）
          └── Hermes Adapter（会话/推理/Skills/工具/流）
                 └── Hermes Agent Runtime（唯一 Agent Runtime）
                         ├── 对话与计划
                         ├── 自主经验/Skill 学习（按风险受控）
                         └── 自动记忆关联/工具化事实核验

NAS 文件业务 SoT：20-Knowledge / 30-Projects / 40-Memory / 50-Journal
    Raw + Review 保留可追溯原件；Private 默认无挂载、无索引。
```

### 每轮对话
1. 处理显式行动意图与安全边界：普通闲聊不触发擅自 Journal/Capture/待办写入；获明确指令时走相应 Core 语义 API。
2. 对普通对话获取少量稳定 L1 以及与当前话题相关的 L2/L3/L4 线索（主动而非仅靠用户下令搜索），限制 token/延迟；当需数值、精确事实、版本或最近状态时由 Hermes 自动核验原件。
3. Hermes 在有来源上下文基础上进行判断，回答可自然引用背景；对会改变结论的事实给出来源，不强行每句话引用。
4. 对话后异步学习获准范围的低风险记忆；允许用户查看“我记住了什么”、纠正、撤销；保留来源、时间及推断标记。

### 任务/文件/通知
- Journal/Task/Capture 只由明确操作意图或已授权的规则触发；成功以 Core 落盘/状态为准，非模型口头声称。
- 主动建议可在 Home/Today 聚合；提醒的“待办落盘”和“通知真实送达”单独验收；执行/发送/删除按动作风险授权。
- Organizer 原 D076 配置与软件预算边界不直接等于 Personal Learning Loop。是否复用其调度/游标由实测决定；避免同一消息重复处理或双重调度。

## 6. 安全、成本、可用性（不降低现有底线）

- Hermes 无正式 `20-Knowledge` RW、无 Core 审批凭据；Private 不挂载；Memory 写入只能通过隔离的细粒度通道，不扩大现有 Hermes 任意文件写入权限。
- 对个人记忆允许默认自动学习，但提供关闭/清除纠正、来源与敏感内容的可见控制；Private 仍绝对排除。
- 外部模型处理真实会话/个人记忆需单独核准数据范围、提供商、凭据、预算和泄露风险。可优先本地预处理或少量脱敏；不能把本地软预算冒充供应商硬上限。
- 保持两个核心部署服务（App/Core + Hermes）、GitHub 代码文档 SoT、NAS 业务文件 SoT；Mac/Obsidian 的实际同步仍需验收。
- 回答质量与延迟优先，实行分层摘要、相关性/新鲜度排序与事实核验。是否增设搜索索引、语义召回或重模型，按真实基准测试而非概念营销决定。

## 7. 分阶段路线、返工和验收

### Phase 0：初始只读核验与隔离实验（历史路线，已部分完成；不是当前 NEXT）
1. 从 GitHub 最新 main 与最后 NAS 运行快照核实：当前 Chat→Hermes 请求路径、Hermes 版本/能力、原生记忆/学习是否开启、会话读取、知识召回方式、`40-Memory` 内容/权限、Organizer 状态；不得把文档快照当作实时运行结果。
2. 读当前安装版本的实际接口/配置，再按必要性核对 Hermes 官方 stable 的 Memory Provider、pre-turn recall、post-turn learning、Skills 自主学习、调度支持；区分“官方最新版存在”和“当前版本已具备”。
3. 在完全隔离的测试会话及**合成数据**里做 4 组基准：不提示搜索的主动联想；跨会话自动记忆；纠正后更新；需要数字/版本时自动读取来源。记录成功/遗漏/误召回、token、时延和调用费用。
4. 比较最小可用路线 A：Hermes 原生记忆机制；B：在现有 App/Core/BFF 层提供最小受控记忆召回/记录。优先原生接口；若原生钩子不可用，不为试验强行升级生产。提出选型、最小改动范围、风险和回滚。
5. 输出技术验证报告与下一阶段 Codex 施工任务，再单独申请需要的代码/生产权限。未经确认**不**升级 Hermes、不修改 NAS/Compose/Secret/ACL、不启用整理器或真实数据出站。

### Phase 1：Companion MVP（必须真正体现“了解我”）
- 可审计的个人记忆：稳定偏好、经历、变化、来源、版本、纠正/失效；低风险学习默认自动。
- 普通 Chat 默认主动联想已知背景，必要时自动事实核验；跨会话有效。
- 自然语言 Journal/碎碎念追加、简单待办管理、文件收录与现有 Raw/Review/Human Promote 联通，不丢原始输入。
- Hermes Skill 自主学习按实际支持能力验证，敏感 Skill 审核不削弱。
- 在真实授权小样本和合成测试集上通过 Section 8 的质量门槛，才允许标记 MVP 完成。

### Phase 2：现有 V1 业务闭环与多端收口
- 完成旧 V1 全部 MUST：微信、Web 多格式输入、Promote 安全上线、Projects/Brief/Activity、Home/Calendar 真数据、LAN/HTTPS 与桌面/移动端验证、恢复和 Obsidian 同步。原 V1 MUST 不因战略升级自动取消。
- Organizer 的“形成 Review 草稿”与新学习闭环并行但不重复；确保数据质量与费用、权限边界。

### Phase 3：主动规划伙伴
- 项目/目标/待办/日历事件变化驱动有依据的主动建议；可配置频率、静默期、去重、状态反馈。
- 从建议→你的决定→行动结果→经验修正构成完整反馈循环；在保证授权下逐步扩大低风险自动化。
- Jev、世界模型、重型 RAG/向量和知识图谱均不在默认依赖中，只有测试证实缺口及明确收益后再提案。

## 8. 可重复的产品验收门槛（目标已批准；数值指标待 Phase 0 基线后冻结）

1. **零检索提示：** 不使用“搜索/查知识库”字眼，普通对话能自发运用先前确实存在的偏好、项目经历、决策理由。
2. **跨会话继承：** 新会话在相关时能准确体现前次明确偏好；无关主题不强行联想。
3. **纠正与时间演进：** “我已经改变想法”后，旧记忆不继续被当作当前事实；能解释变更来源。
4. **反幻觉：** 不把第三方报告当成个人数据、不把 AI 推断当作用户明示，也不凭记忆编造精确数值；必要时自动核查原件。
5. **碎碎念与日记：** 明确记录指令追加原文、可追溯日期/来源；普通闲聊不意外落日记。
6. **待办：** 创建、查看、调整、完成真实状态一致；提醒成功与通知送达分开验证。
7. **文件：** 原件不覆盖、抽取和 Review 可检查、必要时自动关联、未经批准不 Promote。
8. **学习：** 重复反馈能形成有依据的经验，在后续相似问题运用；不能反复学习同一条而无限增长。
9. **主动建议：** 给出与真实目标/事件相关的建议且有来源，不伪称已经执行。
10. **安全与经济性：** Private 不可见、Knowledge 不可被 Agent 直接写入、可恢复；观测延迟和模型费用不无界增长。

**验收状态规则：** 文档批准 ≠ 代码实现 ≠ 测试通过 ≠ NAS 部署 ≠ 用户验收。当前仍为原 V1 NOT DONE，以上新增 Companion 能力均视为未验收，不能写成生产可用。

## 9. 技术选型与尚待验证的事项（明确不是既成事实）

- **APPROVED：** 产品目标、自然联想、自主低风险学习、正式知识人工审核、双闭环、原有使用场景保留、Hermes 主线、NAS 数据持久性与私人数据边界。
- **PREFERRED / NEEDS EVIDENCE：** 原生 Memory Provider 优先、逻辑四层记忆、记忆写入 Core 细粒度接口、项目/任务事件驱动主动建议；具体当前 Hermes 版本是否支持需先确认。
- **DEFERRED：** Jev、Jev-Mem、世界模型、Honcho/Mem0 等独立记忆平台、知识图谱、向量 DB、第二 Agent Runtime；并非永不使用，只是不因概念先部署。
- **OPEN：** 具体记忆格式与目录内写入权限、冲突/失效与重建算法、provider/adapter 最终选择、学习触发频率、真实数据的默认学习授权范围、主动建议触发条件、提醒的送达通道；明天按 Phase 0 验证，不让未决定项阻塞已能测试的流程。
